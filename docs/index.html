mooncat

An ASGI 3.0 server for MoonBit. It accepts a connection, turns each request into a scope, a receive and a send, and drives your application — over HTTP/1.1, HTTP/2, HTTP/3 and WebSocket, on one port.

$ moon add moonbitstack/mooncat
Get started Watch it negotiate
  • ASGI 3.0the interface an app is written to
  • h1 · h2 · h3HTTP over TCP and over UDP
  • 12000the default port
  • native · wasmserves where the async sockets are

What it doesthe whole job, in one picture

mooncat owns the half of a web server that is not the protocol: the listening socket, the connection, the request that arrives on it in pieces, and the answer that leaves in pieces. It hands the application a scope describing the request and two callables — one to read the body, one to write the response. Everything else, from routing to templates, belongs to the application.

One port, every version

The listener decides as the connection opens. Under TLS the choice is made in the handshake; in the clear it is the first bytes on the wire. Either way the request lands in the same place.

On the wireDecided byWhat the application sees
HTTP/1.1the request line, in the clearan http scope; the body one piece at a time
HTTPSa TLS handshake with h2 and http/1.1 offeredthe same scope, with scheme https and the certificate in extensions
h2cthe connection preface PRI * HTTP/2.0the same scope, once per stream
HTTP/2ALPN answering h2one scope per stream, each stream in its own task
HTTP/3the same port number on UDPone scope per stream, advertised by alt-svc
ws · wssUpgrade: websocket, at the starta websocket scope: connect, accept, receive, send, close

Quick start

shell
moon add moonbitstack/mooncat
moon add moonbitstack/moonasgi

An application is a function of three arguments. It answers with two events:

src/main.mbt
/// A server that greets whoever connects.
async fn main {
  let app : @moonasgi.AsgiApp = (_scope, _receive, send) => {
    send(
      @moonasgi.Event::HttpResponseStart(
        status=200,
        headers=[("content-type", "text/plain; charset=utf-8")],
        trailers=false,
      ),
    )
    send(@moonasgi.Event::HttpResponseBody(body=b"hello from mooncat\n", more_body=false))
  }
  @mooncat.serve(app, host="127.0.0.1", port=12000)
}
shell
moon run src/main --target native
curl -i http://127.0.0.1:12000/

The packages

A program that answers only over TCP links none of the UDP half. The split follows what a package costs to carry, not how it reads.

PackageWhat it is for
mooncatthe entry points, re-exported, so @mooncat.serve is all a small program needs
mooncat/configConfig, the access and error log, the HTTP date
mooncat/lifespanstartup before the listener, shutdown after it
mooncat/proxythe client and scheme a trusted proxy reports
mooncat/servethe accept loop, HTTP/1.1, HTTP/2, WebSocket, TLS, workers
mooncat/clithe command line, and run(app) as a whole program
mooncat/quicHTTP/3: the UDP socket, the datagram loop, and the streams

Serving runs where the async sockets do — the native and wasm backends — and the test suite runs on both. The QUIC half is native only.
