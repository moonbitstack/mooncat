    mooncat29 items

    The entry points, re-exported: what a program that serves one application needs, and nothing it does not.

    Values

    fnfn early_data(@spec.Scope) -> Bool

    Whether this scope's request may be a replay: it arrived in 0-RTT, before the handshake that would have proved the client owns its address (RFC 8470). A request forwarded by a proxy that took it in 0-RTT says so with Early-Data: 1, so both are read.

    letlet early_data_size : Int32

    How much a client may send in 0-RTT under one ticket, in bytes: 16 KiB, room for a request head and a small body, small enough that replaying one costs little.

    fnfn http_date(Int64) -> String

    Format a Unix-epoch millisecond count as an HTTP-date in the IMF-fixdate form RFC 7231 §7.1.1.1 makes mandatory for a Date header: Sun, 06 Nov 1994 08:49:37 GMT, always GMT, always fixed-width.

    The calendar and the format are moondate's; what is here is the millisecond clock mooncat reads, brought down to the whole second the header is written to.

    fnfn http_date_now() -> String

    The current instant as an HTTP-date, reformatted only when the epoch second has moved on.

    letlet port : Int32

    The default port for the TCP serving entry points.

    HTTP/1.1, WebSocket upgrades and HTTP/2 share one listener, told apart by ALPN under TLS and by the HTTP/2 preface in the clear. quic_serve takes an explicit UDP address; it may use the same number because UDP and TCP have separate port spaces.

    fnfn proxy_rewrite(Map[String, String], (String, Int32)?, String, trusted~ : Array[String], websocket? : Bool) -> ((String, Int32)?, String)

    Rewrite a request's client and scheme from a trusted proxy's forwarding headers (← uvicorn's ProxyHeadersMiddleware).

    Nothing is rewritten unless the peer itself is trusted: these headers are attacker-controlled, and believing them from an arbitrary client lets that client name any address it likes for a rate limiter, an allowlist or an audit log. Behind a proxy the peer is the proxy, which is why forwarded_allow_ips defaults to 127.0.0.1 and not to *.

    X-Forwarded-For yields the chain's leftmost entry with port 0, since a forwarded chain carries no port. X-Forwarded-Proto replaces the scheme, mapped to wss/ws for a WebSocket scope, whose scheme names differ from the https/http the header spells.

    fnasync fn read_frame(&@io.Reader, client? : Bool, limit? : Int32) -> @ws.Frame

    One frame off a stream (RFC 6455 §5.2).

    The header is read in the order the format is laid out — two bytes, then the extended length, then the mask — and @ws.check runs on the header before the payload is read, so an enormous announced length is refused rather than allocated.

    client is the server's position by default: a client's frames must be masked (§5.1), so reading a server's frames takes client=false. Raises @ws.Refused carrying the status the connection is then failed with, and passes the stream's end through.

    fnasync fn read_message(&@io.Reader, &@io.Writer, limit? : Int32) -> @ws.Message

    One complete message off a stream, with the control frames between its fragments handled: a ping is answered on writer, a pong is dropped, and a close is echoed before the message comes back as that close.

    This is the server's receive path, so every frame must arrive masked. The reply frames go out unmasked because a server must not mask (§5.1).

    fnasync fn reload_watch(String, async () -> Unit) -> Unit

    Watch path for source changes and fire on_reload on each batch of events (← uvicorn's --reload file watcher). Backed by @fs.Watcher, which debounces and reports child-file events, so a save to any file under path triggers one reload. on_reload is where a supervisor re-execs the server; wiring it to a ShutdownHandle turns a file save into a graceful restart. Loops until its task is cancelled, always closing the watcher.

    fnasync fn serve(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, host? : String, port? : Int32, backlog? : Int32, listening? : @serve.Listening) -> Unit

    Serve under a plan already parsed, for a program that wants to look at the plan — or change it — before the socket opens.

    fnasync fn serve_config(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, listening? : @serve.Listening) -> Unit

    Serve HTTP/1.1, HTTP/2 and HTTP/3 together under one certificate, TCP and UDP on the same port: the TCP side tells clients about HTTP/3 with alt-svc (RFC 7838).

    With workers above 1 the TCP port is shared by the kernel, as for serve_tls, and the UDP port by this process: it holds the socket and passes each datagram to the worker whose number is in the connection id (see route.mbt).

    Session resumption is on over TCP and UDP alike, each worker with keys of its own, so a ticket resumes only on the worker that sealed it. tickets chooses the keys: pass the same ones to share tickets across workers, or @tls.tickets to turn it off.

    transport is the QUIC configuration itself — Retry, the idle timeout, the flow-control credit. With workers above 1 it reaches this process only: the workers are started again from the command line, so they take the default, while everything on Config does reach them through the flags that were typed.

    Config.early_data decides what a request sent in 0-RTT gets: taken and marked with Early-Data: 1, answered 425 Too Early without running the application, or not offered at all (RFC 8470). Config.early_data_size is the allowance one ticket carries. Over TCP there is no early data whatever it says: a byte stream cannot hold a request back until the handshake says whether to take it, so only the QUIC listener offers any.

    fnasync fn serve_graceful(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, handle? : @serve.ShutdownHandle, listening? : @serve.Listening) -> Unit

    Serve a moonasgi application with a uvicorn-style process model: a graceful shutdown path over a single acceptor that spawns a concurrent handler per connection.

    The lifespan protocol runs startup before the listener binds and shutdown on the way out. A single acceptor task spawns one handler task per connection, so requests are served concurrently, each through mooncat's HTTP/1.1 codec and, on an upgrade, its WebSocket bridge. serve, serve_config and serve_tls_config run this same loop; this entry point adds the handle.

    Shutdown is triggered by handle.shutdown() / handle.request_stop(), by reaching Config::limit_max_requests, or by a signal the runtime turns into global cancellation (see the boundary note below). All three converge on one sequence, run under protect_from_cancel so a signal can't abort it midway: stop accepting (cancel the acceptor), drain in-flight requests (bounded by Config::graceful_timeout), run the ASGI lifespan shutdown, then close the listener.

    The acceptor honours the connection ceilings: max_connections gates accepting, so a full server leaves the next client in the listen queue rather than accepting it and sitting on it, and allow_failure decides whether one bad connection is contained or brings the server down. limit_concurrency is the other kind of ceiling — a request arriving past it is answered 503 rather than queued.

    ## Several workers

    With Config::workers above 1 this process only supervises: see supervise. Each worker comes back through this same function, binds the port under SO_REUSEPORT, and serves as described here.

    ## Signal boundary

    The only signal hook moonbitlang/async exposes is @signal.set_global_cancellation_signals, which cancels the whole task tree on SIGINT/SIGTERM. mooncat catches that cancellation and still runs lifespan shutdown and closes the listener under protect_from_cancel; but a signal also cancels the in-flight handler tasks, so drain-before-close is only fully honoured on the programmatic ShutdownHandle path. That matches uvicorn's own escalation: a first signal drains, a second forces exit.

    fnasync fn serve_h2c(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, host? : String, port? : Int32, listening? : @serve.Listening) -> Unit

    Serve a moonasgi ASGI application over HTTP/2 cleartext (h2c) only — the prior-knowledge, no-TLS HTTP/2 profile (RFC 9113 §3.3). Convenience wrapper over serve_h2c_config that builds a Config from host / port. Blocks in the accept loop until the running task is cancelled.

    serve and serve_tls speak HTTP/2 as well, beside HTTP/1.1 on the same port; this entry point is for a listener that is to speak nothing else.

    fnasync fn serve_h2c_config(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, listening? : @serve.Listening) -> Unit

    Serve a moonasgi ASGI application over h2c under an explicit Config: the same serving loop as serve_config, with its lifespan, limits, logging and graceful shutdown, on a listener that speaks HTTP/2 alone.

    fnasync fn serve_tls(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, certificate_file~ : String, private_key_file~ : String, password? : String, host? : String, port? : Int32, backlog? : Int32, listening? : @serve.Listening) -> Unit

    Serve a moonasgi ASGI application over native HTTP/1.1 over TLS (HTTPS, ← uvicorn's --ssl-certfile/--ssl-keyfile). Convenience wrapper over serve_tls_config that builds the Config from host/port/backlog and the certificate paths.

    Runs the full ASGI lifespan protocol around the accept loop (startup before the listener binds, shutdown on exit — even under cancellation), then, for every accepted connection, completes a TLS handshake and serves HTTP/2 when ALPN settles on h2, HTTP/1.1 otherwise.

    A WebSocket upgrade on an HTTP/1.1 connection is served too (wss://): the 101, the subprotocol echo and the frames all travel over the encrypted stream.

    fnasync fn serve_tls_beside(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, @tls.Server, async (@serve.Site) -> Unit, alt_svc? : String, listening? : @serve.Listening) -> Unit

    Serve over HTTPS with another listener beside the TCP one, which runs from the moment the application has started until the requests in flight everywhere have drained.

    alt_svc is a header value to advertise the neighbour with, in which {port} is replaced by the port the socket actually got — which is the only way to name it when the caller asked for port 0.

    fnasync fn serve_tls_config(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, @serve.TlsCert, listening? : @serve.Listening) -> Unit

    Serve a moonasgi ASGI application over HTTPS under an explicit Config and TlsCert. Mirrors serve_config: lifespan startup is driven before the listener binds and shutdown on the way out (guarded by protect_from_cancel so it still runs when the serving task is cancelled), and each accepted connection completes a TLS handshake within timeout_handshake and then runs the same loop as a plain one.

    fnasync fn serve_tls_server(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, @tls.Server, listening? : @serve.Listening) -> Unit

    Serve over HTTPS with a TLS configuration built by the caller: the suites, the groups, the ALPN list and the certificates are all server's. serve_tls_config is this with the configuration read from PEM files.

    The lifespan protocol: an application invoked once before the listener binds and once on the way out.

    Errors

    errorsuberror LifespanError

    Raised when the lifespan protocol stops the boot or reports a failed shutdown: the application sent lifespan.startup.failed or lifespan.shutdown.failed, or it raised under Lifespan::On. Carries the application's message.

    LifespanError(String)

    Types and methods

    structstruct Driver

    Drives an application's lifespan protocol (← uvicorn's LifespanOn).

    One invocation of the application runs under a Lifespan scope for the server's whole life: startup sends lifespan.startup and waits for the answer, shutdown sends lifespan.shutdown. state is the scope's namespace; the server gives every request scope a shallow copy, so what startup stores there reaches each request.

    mode is uvicorn's --lifespan: under Auto an application that fails on the lifespan scope, as one serving only HTTP does, is taken not to speak the protocol and the server carries on; under On that failure stops the boot; under Off nothing runs.

    state : Map[String, @json.Json]
    fnfn Driver::new(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, mode? : @config.Lifespan, logger? : @config.Logger, state? : Map[String, @json.Json]) -> Self

    A driver for one application. spawn parks the application under a Lifespan scope, and startup / shutdown deliver the two messages to it in that order. state is what the startup writes down for the scopes that follow, which is why it is a parameter and not a field the caller sets afterwards.

    fnasync fn Driver::shutdown(Self) -> Unit

    Run lifespan shutdown: send lifespan.shutdown and wait for the answer, unless the invocation has already ended. Raises LifespanError on lifespan.shutdown.failed, and on a failure of the application under On.

    fnfn Driver::spawn(Self, @async.TaskGroup[Unit]) -> Unit

    Start the lifespan invocation as a task in g. It waits on receive() until startup and shutdown send it something; its failure is contained, and reported through them.

    fnasync fn Driver::startup(Self) -> Unit

    Run lifespan startup: send lifespan.startup and wait for the answer. Returns on lifespan.startup.complete, and when the application returns without answering. Raises LifespanError on lifespan.startup.failed, and on a failure of the application under On; under Auto such a failure means the application does not speak the protocol.

    structstruct ShutdownHandle

    A handle for driving a graceful shutdown of serve_graceful from outside the serving task (← uvicorn's Server.should_exit / handle_exit). Hand one to serve_graceful, then call shutdown() from any other task to stop the server: it stops accepting, waits for in-flight requests to drain, runs the ASGI lifespan shutdown, and closes the listener, in that order.

    Two async queues carry the handshake. request receives the shutdown trigger (a signal delivered through the runtime's global cancellation reaches the server the same way — see serve_graceful). done is posted once the server has finished the whole shutdown sequence, so shutdown() can block until the port is actually free.

    fnasync fn TlsCert::load(Self, alpn? : Array[String], suites? : Array[@record.Suite], suites12? : Array[@record.Suite12], tickets? : @tls.Tickets, early? : Int32) -> @tls.Server

    Read the files into a TLS server configuration. A key that is not the leaf's is refused here, at startup, rather than by every client's handshake.

    fnfn now() -> Int64

    The event loop's clock, in the microseconds the recovery and idle timers are measured in. @async.now() counts milliseconds since the epoch.

    fnasync fn serve(String, @conn.Endpoint[@socket.Addr], tick_ms? : Int32) -> Unit

    Bind a UDP socket at addr (e.g. "0.0.0.0:443") and serve server on it. The socket outlives the loop deliberately: closing one a task is parked in recvfrom on wedges it rather than waking it, so shutdown is cancellation of the task group, not a close.

    fnasync fn serve_config(async (@spec.Scope, async () -> @spec.Event, async (@spec.Event) -> Unit) -> Unit, @config.Config, @serve.TlsCert, suites? : Array[@record.Suite], suites12? : Array[@record.Suite12], tickets? : @tls.Tickets, transport? : @conn.Config, listening? : @serve.Listening) -> Unit

    Serve HTTP/1.1, HTTP/2 and HTTP/3 together under one certificate, TCP and UDP on the same port: the TCP side tells clients about HTTP/3 with alt-svc (RFC 7838).

    With workers above 1 the TCP port is shared by the kernel, as for serve_tls, and the UDP port by this process: it holds the socket and passes each datagram to the worker whose number is in the connection id (see route.mbt).

    Session resumption is on over TCP and UDP alike, each worker with keys of its own, so a ticket resumes only on the worker that sealed it. tickets chooses the keys: pass the same ones to share tickets across workers, or @tls.tickets to turn it off.

    transport is the QUIC configuration itself — Retry, the idle timeout, the flow-control credit. With workers above 1 it reaches this process only: the workers are started again from the command line, so they take the default, while everything on Config does reach them through the flags that were typed.

    Config.early_data decides what a request sent in 0-RTT gets: taken and marked with Early-Data: 1, answered 425 Too Early without running the application, or not offered at all (RFC 8470). Config.early_data_size is the allowance one ticket carries. Over TCP there is no early data whatever it says: a byte stream cannot hold a request back until the handshake says whether to take it, so only the QUIC listener offers any.

    fnasync fn serve_endpoint(Endpoint, @conn.Endpoint[@socket.Addr], tick_ms? : Int32) -> Unit

    Serve QUIC on ep until the enclosing task group is cancelled: one task reads datagrams and demultiplexes them onto connections, the other runs the idle, probe and closing-period timers every tick_ms milliseconds, and both push out whatever that left ready to send. A datagram that names no connection or fails to authenticate is dropped rather than killing the loop — an endpoint cannot tell a stray packet from an attack.

    Serve HTTP/3 beside the server's TCP listener, on UDP at the same address, until cancelled. tls offers h3.
