    指南

    从一个应用开始，逐项讲配置、命令行、TLS、WebSocket、HTTP/2、HTTP/3、lifespan、多 worker 与代理头。代码都能编译，终端块都是运行输出。

    第一个服务器

    装两个包：服务器与接口定义。

    ASGI 应用是接受三个参数的异步函数：scope、读请求体、写响应。

    serve 绑定套接字，停在接受循环里，直到任务被取消。

    server 与 date 由服务器添加，都可关闭。单段响应按正文算 content-length，分段响应改用 chunked。

    scope 里有什么

    请求以 scope 到达。下列字段在三代 HTTP 上一致。

    字段HTTP 请求上WebSocket 上
    http_method"GET"、"POST" …—
    path · raw_path百分号解码后的，以及原样的字节—
    query_string字节，不含 ?—
    headers名字小写，重复的字段都留着升级请求的 headers
    scheme"http" 或 "https"，经代理头改写"ws" 或 "wss"
    client · server对端与监听端，都是 (host, port)同上
    http_version"1.0"、"1.1"、"2"、"3""1.1"
    root_path前面的东西剥掉的前缀同上
    statestartup 存下的东西的浅拷贝同一份拷贝

    流式读取请求体

    请求体不整块收下：每次 receive() 给出已到的片段，并说明后面还有没有。

    可以先作答再读完：剩余部分被读掉或关闭连接，不会当成下一个请求。请求体交完后，receive() 等到响应结束或客户端离开才给 http.disconnect。

    WebSocket

    握手完成前是一次普通请求；之后 scope 变成 websocket，同一对 receive/send 改说帧。ws:// 与 wss:// 共用一条路径。

    握手实录：

    帧有校验：RSV 置位、保留操作码、未掩码帧、畸形控制帧都以 1002 断开；超过 ws.max_size 在读载荷前以 1009 拒绝；非法 UTF-8 以 1007 失败；关闭帧按规范回显。

    Config.ws默认作用
    max_size16 MiB能收下的最大消息
    max_queue32等着应用的讯息；满了就停止读取，客户端被 TCP 挡住
    ping_interval20000 毫秒保活 ping 的间隔；None 关掉
    ping_timeout20000 毫秒对端没按时回 pong 就以 1011 关闭
    deflatetrue客户端提出 permessage-deflate 时接受

    ping 由服务器应答，不交给应用。升级前拒绝回 403。

    HTTP/2 与 h2c

    serve 与 serve_tls 已在同端口上说 HTTP/2：TLS 下由 ALPN 点名 h2，明文下看前言。应用不用改。

    serve_h2c 只说 HTTP/2，不嗅探、不回落：

    每条流一个任务，慢处理器只拖住自己。请求体随索取而到，窗口按这个节奏还回。

    Config.h2默认作用
    max_streams100并发流数；多出来的以 REFUSED_STREAM 拒掉
    max_header_list64 KiB一个头块允许的字段
    max_frame16 KiB服务器愿意发的最大帧
    window1 MiB单条流的流控窗口
    connection_window1 MiB整条连接的流控窗口

    限额按流算：超过 limit_concurrency 回 503，每条流计入 limit_max_requests，timeout_keep_alive 内无流则发 GOAWAY。客户端的 RST_STREAM 变成 http.disconnect。响应前出错回 500，之后用 INTERNAL_ERROR 重置。

    应用给 http_version 答的是 "3"。每条流一个任务，响应按客户端已确认的部分推进。

    单进程。 UDP 端口还不能在 worker 间共享，--http3 配多个 --workers 会被拒。停机发 GOAWAY，已接下的流在 timeout_graceful_shutdown 内跑完。

    lifespan

    应用在监听前与退出前各被调用一次，都在 Lifespan scope 下。连接池在这里开关。Config.lifespan 决定严格程度：

    模式行为
    Auto照跑；在 lifespan scope 上失败的应用照样服务
    On照跑；在它上面失败，服务器就不启动
    Off完全不跑

    startup 放进 state 的东西以浅拷贝进入每个 scope。服务任务被取消时 shutdown 照样跑。

    顺序。 要求停机时在飞的请求先做完，客户端仍拿到 200；之后跑 lifespan shutdown，最后关监听器。

    多 worker

    workers 把程序跑若干份，共享一个端口。被启动的进程自己不服务，只监督。

    每个 worker 自己绑定端口、跑 lifespan，内核分摊连接。死掉的被替换，limit_max_requests 也这样退休。起不来的 worker 让监督进程以退出码 3 结束。停监督进程即停全部，各自按 timeout_graceful_shutdown 排空。

    仅 Linux：只有它的内核在绑到同一端口的套接字间分摊连接。别的系统会拒绝该设置。缺省时由 WEB_CONCURRENCY 决定。

    代理头

    负载均衡后面，对端地址是均衡器的。proxy_headers 让服务器相信 X-Forwarded-For、X-Forwarded-Proto、Forwarded，但只对 forwarded_allow_ips 里的对端。

    * 表示相信所有对端，仅在套接字不可外达时安全。proxy_rewrite 是同一判断的函数形式。
